# לב המעבר™ — פיילוט

מלווה חכם לבני משפחה המטפלים בהורה מבוגר, מבית **בינה מעברית™**.
בנוי לפי מסמך "אסטרטגיה ופרומפט מאסטר — לב המעבר™ v3.0" (עברית בלבד, RTL מלא).

## הפעלה מקומית

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # build לתיקיית dist/
```

## מה בנוי בפועל בגרסה הזו

אפליקציית React (Vite) חד-עמודית, **ללא שרת אחורי** — כל הנתונים נשמרים ב-`localStorage` של הדפדפן. זוהי הדרך המעשית להדגים את מלוא היקף הפיילוט (מסך אחר מסך, ישות נתונים אחר ישות נתונים) ללא תשתית שרת/DB/Auth שלא הוגדרה במסמך.

כלול ופעיל:
- כל 16 המסכים מהיקף הפיילוט (ליבה + מתקדם + ניהול פיילוט), מדורגים ("עוד יכולות" פותח את המסך המתקדם).
- מודל הנתונים המלא מסעיף 6 (FamilySpace, Parent, User, Membership, ConsentRecord, Medication, MedicationLog, Inventory, Measurement, Appointment, Shift, Task, Document, VisitReport, Alert, AutomationRule, AuditLog).
- אשף הקמה מודרך + מצבי ריקים בכל מסך.
- הרשאות לפי תפקיד (6 תפקידים), כולל חסימת הסרת מנהל יחיד.
- חמש האוטומציות של הפיילוט, פועלות על נתונים אמיתיים במחזור של 60 שניות + עם כל שינוי נתונים.
- מצב שבת וחג: חישוב אסטרונומי מקורב של כניסת/יציאת שבת לפי עיר, השתקת התראות בזמן שבת וריכוזן ב"סיכום מה שהצטבר בשבת".
- סוכן מבוסס-כללים (לא LLM חי — ראו הסבר למטה) שקורא רק נתונים מקומיים, מזהה מצבי חירום ומסמן מקור לכל תשובה.
- יומן פעילות מלא, לוח מדדי הצלחה למנהל הפיילוט, שני הדוחות (שבועי + הכנה לרופא) עם הדפסה/PDF.
- נגישות: ניווט מקלדת, תוויות ARIA, הגדלת גופן וניגודיות גבוהה, אישור לפני מחיקה/ביטול.

## מה סימולציה בלבד, ולמה (כדי לא להטעות)

המסמך המקורי (סעיף 41) קובע במפורש שאסור להעלות פיילוט חי עם משפחות אמיתיות לפני שורת אישורים (אבטחה, פרטיות, משפטי, נגישות ועוד). בהתאם לכך, הגרסה הזו היא **הדגמה טכנית**, לא מוצר מוכן לנתוני אמת:

- **אין שרת, אין הצפנה אמיתית, אין MFA.** ההתחברות מקומית בלבד (hash חלש להדגמה), והנתונים גלויים ב-localStorage של הדפדפן. אין הפרדת סביבות, אין הצפנה במנוחה/בתעבורה.
- **"משפחה מרובת מכשירים" מדומה בדפדפן אחד.** הזמנת בן משפחה יוצרת קוד הצטרפות מקומי; כדי שבן משפחה אחר יצטרף באמת ממכשיר נפרד יש להוסיף שרת+DB+Auth אמיתיים.
- **הסוכן הוא מנוע כללים דטרמיניסטי, לא מודל שפה.** הוא עונה רק על השאלות המוגדרות מראש בסעיף 20, קורא נתונים מקומיים בלבד ומכריז בפירוש כשאין לו תשובה — לפי עקרון "לא ממציא נתונים". חיבור לסוכן LLM אמיתי (עם שכבת הרשאות/הסכמה מלאה) הוא עבודת שלב הבא.
- **מסמכים נשמרים כמטא-דאטה (שם קובץ) בלבד**, לא כתוכן — כדי לא לאחסן מידע רגיש בלי הצפנה אמיתית. "סיכום סוכן" למסמך הוא הודעת placeholder כנה, לא ניתוח תוכן בפועל.
- **דחיפה למכשיר, דוא"ל והתראות SMS אינם ממומשים** (גם לא נדרשים בפיילוט לפי סעיף 1) — יש רק התראות בתוך האפליקציה.
- **חישוב זמני שבת הוא קירוב אסטרונומי** (משוואת שקיעה כללית), לא לוח זמנים הלכתי מוסמך.

## לפני פיילוט חי עם משפחות אמיתיות

יש להשלים את כל קריטריוני הקבלה שבסעיף 41 במסמך המקור: בדיקת בטיחות קלינית, בדיקת חדירות, הערכת השפעה על הפרטיות, בדיקת נגישות AA מלאה, בדיקות הרשאה/גיבוי/שחזור/עומס, אישור משפטי לתנאי שימוש והסכמה, ותכנית תמיכה וסיום פיילוט — ולבנות שרת/DB/Auth אמיתיים תחת הארכיטקטורה המודולרית שהוגדרה (סעיף 38).
